# Dota 2 技能征召布局几何规范

## 目标

本文说明如何从 Ability Draft 稳定截图计算：

- `12` 个英雄槽、`36` 个普通技能槽和 `12` 个终极技能槽的中心。
- 每个槽位的透视外框 `outerQuad`。
- 用于模板匹配的内框 `matchQuad`。

本文是布局几何的唯一规范来源。资源获取和重新解析方法见 `dota2-ability-draft-resource-parsing.md`；该文档不重复定义相机、槽位和模型顶面几何。

## 核心结论

1. 稳定选技阶段使用 `camera_1`，不是场景初始声明的 `camera_0`。
2. ScenePanel 固定垂直 FOV。常规宽高比应按视口高度等比缩放，并相对视口中心定位；不能分别按屏幕宽度和高度缩放 X/Y。
3. 普通技能、英雄和终极技能都由各自的资源实体、旋转和缩放直接投影，不从截图内容反推布局。
4. `projectAbilityDraftResourceSlots(width, height)` 根据输入分辨率生成最终的 `outerQuad` 和 `matchQuad`。
5. `omg-layout-2560x1440.json` 保留为投影异常、用户导入和手工校准时的固定布局兜底。

## 输入前提

输入截图必须满足：

- 来自 `camera_1` 的稳定选技阶段。
- 相机过渡和技能块初始 `spin` 动画已经结束。
- 不处于悬停抬升、选择旋转或按钮按下动画的中间帧。
- 已知游戏实际渲染视口，不把黑边、窗口边框或桌面区域算入视口。
- 没有经过未知裁切、二次缩放或非等比拉伸。

视口统一表示为：

```text
viewport = (Vx, Vy, Vw, Vh)
```

标准 `2560×1440` 全屏视口为：

```text
Vx = 0
Vy = 0
Vw = 2560
Vh = 1440
```

## 槽位拓扑

```text
hero = 12
ability = 36
ultimate = 12
total = 60
```

- 普通技能：`6` 行 × `6` 列。
- 英雄：普通技能六行的左右两侧各一个。
- 终极技能：`2` 行 × `6` 列。

普通技能和英雄共享资源平面；终极技能使用独立倾角、缩放和高度。

## 世界坐标投影

世界坐标投影直接生成槽位中心和四边形。Dota 2 更新导致相机或实体参数变化时，应先按资源解析文档更新这些常量。

### 相机参数

```text
cameraOrigin = (260.980865, -0.347879, 675.013245)
verticalFov = 45deg

F = (-0.449156324,  0.000085769, -0.893453182)  // 相机前方
R = ( 0.000190956,  0.999999982,  0.000000000)  // 屏幕右方
U = (-0.893453166,  0.000170611,  0.449156333)  // 屏幕上方
```

对任意世界坐标 `P`：

```text
D  = P - cameraOrigin
Xc = dot(D, R)
Yc = dot(D, U)
Zc = dot(D, F)

f = Vh / (2 * tan(verticalFov / 2))

screenX = Vx + Vw / 2 + f * Xc / Zc
screenY = Vy + Vh / 2 - f * Yc / Zc
```

仅当 `Zc > 0` 时点位于相机前方。

### 普通技能和英雄中心

```text
abilityRowX = [-84, -48, -12, 44, 80, 116]
abilityColumnY = [-96, -60, -24, 24, 60, 96]
z = 167.853455
```

```text
ability(r, c) = (abilityRowX[r], abilityColumnY[c], z)
hero(r, 0) = (abilityRowX[r], -144, z)
hero(r, 1) = (abilityRowX[r],  144, z)
```

场景 X 主要映射到截图纵向，场景 Y 主要映射到截图横向，因此 `abilityRowX` 对应截图中的六行。

### 终极技能中心

```text
ultimateY = [-110, -66, -22, 22, 66, 110]

ultimate(0, c) = (-147.718842, ultimateY[c], 213.281158)
ultimate(1, c) = (-116.718849, ultimateY[c], 182.281158)
```

终极技能具有独立倾角、缩放和高度，不能与普通技能共享投影平面。

## 分辨率投影

### `4:3` 及更宽

当 ScenePanel 占满游戏视口且 `Vw / Vh >= 4 / 3` 时，从 `2560×1440` 参考坐标换算：

```text
s = Vh / 1440

x = Vx + Vw / 2 + s * (xReference - 1280)
y = Vy + Vh / 2 + s * (yReference - 720)
```

槽位四边形的局部尺寸也乘以 `s`。

该公式同样适用于精确 `4:3`。不要额外应用 Panorama 的 `ui-scale`，也不要使用 `Vw / 2560` 独立缩放 X。

同高度宽屏只改变水平中心。例如从 `2560×1440` 换到 `3440×1440` 时，棋盘尺寸和 Y 坐标不变，所有 X 坐标增加 `440px`。

### 窄于 `4:3`

窄屏截图按居中的 `4:3` 游戏视口处理，剩余区域视为上下黑边：

```text
effectiveHeight = Vw * 3 / 4
letterboxY = (Vh - effectiveHeight) / 2
s = effectiveHeight / 1440

x = Vx + Vw / 2 + s * (xReference - 1280)
y = Vy + letterboxY + effectiveHeight / 2 + s * (yReference - 720)
```

例如 `1280×1024` 使用居中的 `1280×960` 视口，上下各保留 `32px` 黑边。不会为 `5:4` 建立独立的非等比布局。

## 生成裁剪四边形

裁剪框不再根据截图外框计算固定比例或中心偏移，而是直接投影 Source 2 模型的纹理足迹和底座顶面。稳定状态使用 `camera_1`：

```text
origin = 260.980865 -0.347879 675.013245
angles = 63.310432 179.989059 0
vertical fov = 45
```

不能把模型 POSITION accessor 的三维 AABB 直接当成一个实体表面。图像模型是带斜边的网格，`z=max` 的规则平台仅覆盖纹理 UV `0.011444..0.113529`，而完整技能纹理单元覆盖 `0..0.125`。如果只投影最高平台，宽高都会缩小到约 `81.7%`。

`matchQuad` 使用完整纹理足迹在 `z=max` 平面上的虚拟四边形；其 X/Y 范围来自图像模型完整纹理覆盖范围，而不是最高平台的 X/Y 范围。`outerQuad` 仍使用 `ad_block` 的真实顶面：

```text
image texture x = [-12.4485616684, 12.4485616684]
image texture y = [-12.4485616684, 12.4485616684]
image texture plane z = 1.1875

block face x = [-13.1037511826, 13.1037464142]
block face y = [-13.1037511826, 13.1037464142]
block face z = 25.4375019073
```

每个槽位分别读取图像模型和 `ad_block` 的 `origin`、`angles` 与 `scales`：

- 普通技能和英雄使用实体的零旋转与 `1.0` 缩放。
- 终极技能使用实体的 `45°` pitch 和 `1.1` 缩放。
- `matchQuad` 来自图像模型完整纹理足迹的四个虚拟局部顶点。
- `outerQuad` 来自 `ad_block` 顶面的四个局部顶点。

局部顶点先按 Source QAngle 和实体缩放变换到世界坐标，再使用 `camera_1` 的视图基向量和固定纵向 FOV 投影到当前有效视口。

因此生产裁剪中不存在 `0.76` 裁剪比例，也不存在 `-0.016/-0.038` 经验偏移。模型实体或相机资源变化后，只需重新解析资源快照。

当前模板签名流程使用 `matchQuad` 的轴对齐包围框裁剪，再执行模板匹配。四边形仍用于表达准确的资源投影边界和覆盖层显示。

## 推荐计算流程

1. 确定图片中的真实游戏视口 `(Vx, Vy, Vw, Vh)`。
2. 验证截图处于 `camera_1` 的稳定状态。
3. 依据有效视口和固定垂直 FOV 投影 60 个资源槽位。
4. 生成当前截图中的 `outerQuad` 和 `matchQuad`。
5. 验证槽位数量、类别、四边形面积和截图边界。
6. 使用 `matchQuad` 包围框裁剪并进行模板匹配。
7. 投影结果无效时回退到按截图尺寸缩放的 `omg-layout-2560x1440.json`。

## 使用边界

- 相机、实体、Panorama CSS 和模型顶面是运行时布局的唯一投影输入。
- DPI、UI 缩放、视口裁切、模型 UV、动画和 Dota 2 更新都可能改变最终位置。
- 输入必须是完整游戏截图；未知裁切、二次缩放和非等比拉伸不属于支持范围。
- Dota 2 更新后，应先检查资源相机、槽位实体和相关布局是否变化，再决定是否复用本文常量。
